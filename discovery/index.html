Foodbridge Module Dashboard — Discovery Prototype (wiring hub)

The live prototype tree. v1 is the accepted, frozen snapshot this continues from — see instructions.md.

Iteration goal: recreate the live admin dashboard (b2bgreens.com/platform/dashboard) faithfully enough to argue about what an owner needs to see on landing — and to establish which reports earn a place there. Current iteration (addendum-002) adds a sixth tab, Outstanding Recovery, which groups receivables by cause rather than by debtor; addendum-003 reorders it decision-first, cuts its depth to the ₹299 / ₹999 / ₹2499 personas, and rebuilds it mobile-first.

Three things in this map are derived, not stored, and are the candidates to carry into SSOT-2 (domain model): the recovery owner (us / them, read off the cause — every figure in that tab is a reduction over recoveryOutstanding, so nothing on screen can disagree with anything else), the order-cycle status (daysSince vs the customer's own cadenceDays) and the route-report difference (handedOver − (openingCash + totalCollected − expense), i.e. actual handover minus expected — negative means the salesman is short; it reconciles both seed rows). Data for every screen comes from seed-data/seed.json, mirrored inline in screens/dashboard/seed.inline.js because file:// blocks fetching local JSON.
